## Как учитывается Reddit

Reddit — второй, **независимый от GitHub Trending** сигнал. Для каждой недельной статьи мы публикуем редакционно отобранные датированные ссылки на публичные треды/комментарии, отдельную категорию источника (репост README, личный опыт, критика, внешний тест) и объяснение, какой вывод меняется. Отобранное число — **не** общее количество упоминаний проекта на платформе; перепечатки не являются независимыми benchmark.

Ориентировочный Reddit score иногда указывается по публичной поисковой выдаче, сверенной 09.11.2026, но не объявляется точным историческим значением на дату поста или за календарную неделю. Score не равен числу лайков и может изменяться. До появления одобренного воспроизводимого архива Reddit API **не** формируем рейтинги проектов по Reddit, не суммируем голоса и не подставляем нули при отсутствии найденных ссылок. В каталоге видно количество отобранных Reddit-свидетельств на выпуск; сами ссылки и анализ — внутри статьи.

**Текущий способ поиска — открытый веб-поиск, без регистрации или Reddit OAuth.** По каждому `owner/repo` редакция ищет посты и комментарии, проверяет даты, содержание, источники, отделяет независимые тесты от перепечаток и сохраняет прямые ссылки. [Практическая методика и карточка свидетельства](research/reddit-web-search.md). Публичные публикации можно читать без API-ключа, но доступность отдельных страниц зависит от Reddit. Приватный запрос об особом API-доступе нужен только в будущем, если понадобится исчерпывающая статистика всей платформы, и сейчас не блокирует выпуски.

## Редакционная политика проекта — с 9 ноября 2026

**Сначала проект, затем итог недели или месяца.** GitHub Trending используется только для выявления кандидатов. Редакция сначала изучает новые версии, changelog, смерженные PR, issues и независимые обсуждения Reddit; сравнивает с предыдущей версией, рассматривает альтернативы и сохраняет обновляемую историю проекта. После этого готовится недельный обзор изменений или месячная аналитика. Одни и те же проекты в соседних неделях освещаем как продолжение развития, а не описываем заново.

**Собственные эксперименты не обязательны.** Большие A/B-тесты, GPU/раннеры и установка чужого ПО допускаются лишь по отдельному явному решению. Документальный анализ с проверяемыми ссылками достаточен для публикации, если отделены факты релиза, оценки сообщества и предположения редакции. Ранее выполненные опыты остаются в истории и не считаются типовым этапом. Источник правил: [приватная редакционная политика Research Lab](https://github.com/Dmitry-dev-pet/research-lab/blob/main/docs/oss-radar-editorial-policy.md).

## Редакционный конвейер

1. **Сигнал:** проект попал в датированный дневной/недельный/месячный GitHub Trending. Источник: [GitHub Trending Today](https://githubtrending.today/methodology/) (CC BY 4.0 на составленные рейтинги; лицензии чужого содержимого отдельно). Записываем время исходного снимка, название, период и место в тренде. Сигнал популярности — не оценка качества.
2. **Развитие проекта прежде всего:** проверить релизы, changelog, смерженные PR и issues за период; отличать анонс от реализованной функции и объяснять изменения относительно прошлой недели. README, лицензии, архитектуру и исходники использовать для контекста, а не пересказывать на каждом выпуске заново.
3. **Обсуждения и критический анализ:** выбрать проверяемые публичные Reddit-треды и другие независимые отзывы с датами; отделять репосты и заявления авторов от подтверждённого опыта. Сопоставить ограничения и альтернативы, сформулировать практический смысл релиза. Собственный эксперимент — **по специальному отдельному решению**, не обязателен.
4. **Синтез и публикация:** сначала обновляемое приватное досье проекта, затем недельная история изменений и месячные сквозные тренды. На GitHub Pages только редакционно подготовленный HTML со ссылками на первоисточники. Никаких автоматических LLM-сводок, сырых rankings и рекомендаций по одной метрике.

### Порог качества нового выпуска

Новая статья обязана иметь: указание точного времени трендового сигнала, ссылку на конкретную выдачу/поставщика, минимум один оригинальный GitHub README или исходный файл на каждую тему, чёткие подтверждённые наблюдения и ограничения, проверяемые источники изменений и объяснение их практического значения; если важный вывод основан на неподтверждённом отзыве — явную оговорку об этом. Важные спорные заявления авторов должны оставаться атрибутированными; нельзя назвать README-check результатом запуска кода.

## Сайт

- `index.html` — главная с типизированным каталогом опубликованных **разборов** (не исходных GitHub-репозиториев) и методикой.
- `review-catalog.js` + `reviews/catalog.json` — фильтры по формату (неделя, месяц, глубокий, сравнение, эксперимент) и тематике; только локальный JSON статических публикаций, без внешних API, токенов и аналитики.
- `reviews/*.html` — исходные статьи, включая архивные. На Pages копируются только HTML из `reviews/catalog.json` и перенаправление старого адреса первой недели.
- `style.css` — мобильные стили чтения.
- `.github/workflows/pages.yml` — сборка HTML и GitHub Pages после изменения `main` (или вручную), **без расписания**.
- `tests/test_editorial_site.py` — контрактные проверки редакционного формата, ссылок, лицензии источников и метаданных публикаций перед публикацией.

## Архив, но не текущий продукт

Исторические `data/YYYY-MM.json`, `trends.html`, `trends.js`, `scripts/import_trends.py`, `app.js`, `october.html` и предварительные тесты остаются в истории/source этого репозитория для воспроизводимости первоначального проекта, но **не копируются в публикуемый сайт**. Старый октябрьский обзор отбирал проекты по месяцу создания GitHub-репозитория, а не по попаданию в Trending, поэтому не считается выпуском по новой редакционной методике.

Исходные проверенные снапшоты, происхождение API-данных и рабочие исследования хранятся в приватном [Research Lab, Issue #16](https://github.com/Dmitry-dev-pet/research-lab/issues/16), а крупные архивы — в его приватном хранилище. Нет отдельного ежедневного сборщика и нет планового деплоя ради трендового JSON. Список трендов нужен только как входной материал при подготовке следующего обзора. Приватная очередь наблюдений: [Research Lab #21](https://github.com/Dmitry-dev-pet/research-lab/issues/21); обзоры недели и месяца — после проверки, а не по одному числу звёзд.
