# OSS Radar

Публичный мобильный каталог новых GitHub-проектов, редакторских обзоров и идей для воспроизводимой проверки.

**Сайт:** **https://dmitry-dev-pet.github.io/oss-radar-site/** — опубликован на GitHub Pages. [Обзор октября 2026](october.html) · [Каталог](index.html#catalog).

## Что находится в репозитории

- `index.html`, `style.css`, `app.js` — полностью статический, адаптивный сайт; без сервера, CDN, сторонних шрифтов, трекеров, cookies или API-ключей.
- `october.html` — критический редакторский обзор 10 проектов, появившихся на GitHub в октябре 2026 года.
- `data/manifest.json` — 13 месячных выборок и размеры.
- `data/YYYY-MM.json` — минимальные публичные сведения о **12 188** разных репозиториях: имя, GitHub-ссылка, число звёзд, лицензия из метаданных GitHub, краткое публичное описание и эвристическая категория.
- `.github/workflows/pages.yml` — публикация GitHub Pages только из публичного `main`, без приватных токенов.

## Готовые источники трендов, без собственного сборщика

[Страница «Тренды»](trends.html) читает публичный JSON Feed [GitHub Trending Today](https://githubtrending.today/methodology/) (подборка CC BY 4.0, обязательна атрибуция) и может использовать [OSS Insight API](https://ossinsight.io/docs/api/list-trending-repos) как запасной источник. Позиции отражают методику поставщика, а не собственный рейтинг OSS Radar; в каталог данные не смешиваются. В разделе истории отдельного проекта браузер вызывает [официальный GitHub REST API](https://docs.github.com/en/rest/activity/starring#get-repository-star-history) с недельными/дневными корзинами звёзд.

Никакого GitHub Search API сканирования, нового фонового сборщика, cron, БД, токенов или платной модели в этой функции нет. Результаты и технические ошибки показываются в браузере. **Важно:** браузерные кросс-доменные запросы зависят от разрешения CORS поставщика и его лимитов: внешняя доступность JSON и API описана в документации, но реальная загрузка на Pages требует отдельного browser-smoke. Если источник недоступен, показываются прямые ссылки на оригиналы без фиктивного рейтинга. Подобранные данные из сторонних каталогов не являются верифицированными OSS лицензиями. Неделя/день у GitHub не всегда имеют UTC-границы, а созданные звёзды не являются точным net-приростом.

## Как читать каталог

Выбирайте месяц создания, вводите ключевое слово, сортируйте по текущему числу звёзд, фильтруйте по направлению и наличию **заявленной** лицензии. Избранное сохраняется только локально в вашем браузере (localStorage), без аккаунта и передачи данных.

## Важные границы достоверности

**Это не полный список GitHub и не рейтинг роста звёзд.** Срез получен **8 ноября 2026 года** из публичного GitHub Search API; данные за ноябрь ограничены 1–8 числом. Каждый месяц разбит на пять диапазонов текущих звёзд 50–99, 100–249, 250–499, 500–999 и 1 000–2 000. В каждом диапазоне сохранено максимум по 100 репозиториев с двух концов выдачи. **55 из 65** диапазонов неполные; число проектов в каталоге не отражает реальное распределение популярных проектов.

Звёзды — текущее общее число на 8 ноября, **не прирост за предыдущий месяц**. Дата относится к созданию репозитория, не первому релизу. Лицензия — поле GitHub SPDX, которое может не отражать условия для отдельных моделей, весов, данных или оборудования; независимый аудит не проводился. Тематика определяется эвристически по публичному названию и описанию и может ошибаться.

Материалы сформированы из публичных GitHub README и датированного API-снимка; никаких приватных исследовательских файлов, исходных бинарных архивов, личных ключей или внутренних комментариев в публичном репозитории нет.

## Архитектура

Сбор исходных метаданных, их архивирование и внутренние исследования ведутся отдельно. Этот публичный репозиторий — только витрина из одобренных публичных данных. Страницы работают без обращения к приватным GitHub API, Google Drive или другому backend.

## Локальный просмотр

Откройте репозиторий через локальный HTTP сервер:

```sh
python3 -m http.server 8000
```

Откройте http://127.0.0.1:8000/. Каталог загружается асинхронно через `fetch`, поэтому открытие файла напрямую по `file://` может не работать.
