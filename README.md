# OSS Radar — критические разборы проектов из GitHub Trending

**Публичный сайт:** https://dmitry-dev-pet.github.io/oss-radar-site/

OSS Radar — редакторский журнал. **Вход:** датированные GitHub Trending списки (и при необходимости аналогичные открытые источники). **Выход:** самостоятельные технические разборы интересных проектов. Сайт **не** показывает сырые рейтинги, звёздные счётчики, 12 188 найденных репозиториев или поисковый каталог.

## Выпуски

- [08.11.2026 — четыре подхода к агентной инфраструктуре](reviews/2026-11-08.html): agent-browser, security-audit-skill, OpenMausBot, billion-context. Источник отбора: GitHub Trending Today, снимок 2026-11-08 06:58 UTC; подтверждены README, не выполнялись установки или независимые benchmark.

## Редакционный конвейер

1. **Сигнал:** проект попал в датированный дневной/недельный/месячный GitHub Trending. Источник: [GitHub Trending Today](https://githubtrending.today/methodology/) (CC BY 4.0 на составленные рейтинги; лицензии чужого содержимого отдельно). Записываем время исходного снимка, название, период и место в тренде. Сигнал популярности — не оценка качества.
2. **Проверка первоисточников:** публичный GitHub репозиторий, README, документация, лицензия, исходники и архитектура. Всё проверенное по документам отделяем от маркетинговых заявлений автора, сторонних оценок и наших предположений.
3. **Критический разбор:** не менее одного технического механизма, реального ограничения/риска, альтернативы или применимости, и воспроизводимого теста, который может опровергнуть вывод. При отсутствии живого тестирования явно указываем «документальный разбор».
4. **Публикация:** на GitHub Pages только редакционно подготовленный HTML, ссылки на исходники и методику. Никаких автоматических LLM-сводок, живых rankings и рекомендаций по одной метрике.

### Порог качества нового выпуска

Новая статья обязана иметь: указание точного времени трендового сигнала, ссылку на конкретную выдачу/поставщика, минимум один оригинальный GitHub README или исходный файл на каждую тему, чёткие подтверждённые наблюдения и ограничения, практическую проверку/следующий эксперимент. Важные спорные заявления авторов должны оставаться атрибутированными; нельзя назвать README-check результатом запуска кода.

## Сайт

- `index.html` — главная с выпусками и методикой.
- `reviews/*.html` — только авторские исследования, без автоматических карточек.
- `style.css` — мобильные стили чтения.
- `.github/workflows/pages.yml` — сборка HTML и GitHub Pages после изменения `main` (или вручную), **без расписания**.
- `tests/test_editorial_site.py` — контрактные проверки редакционного формата перед публикацией.

## Архив, но не текущий продукт

Исторические `data/YYYY-MM.json`, `trends.html`, `trends.js`, `scripts/import_trends.py`, `app.js`, `october.html` и предварительные тесты остаются в истории/source этого репозитория для воспроизводимости первоначального проекта, но **не копируются в публикуемый сайт**. Старый октябрьский обзор отбирал проекты по месяцу создания GitHub-репозитория, а не по попаданию в Trending, поэтому не считается выпуском по новой редакционной методике.

Исходные проверенные снапшоты, происхождение API-данных и рабочие исследования хранятся в приватном [Research Lab, Issue #16](https://github.com/Dmitry-dev-pet/research-lab/issues/16), а крупные архивы — в его приватном хранилище. Нет отдельного ежедневного сборщика и нет планового деплоя ради трендового JSON. Список трендов нужен только как входной материал при подготовке следующего обзора.

## Локальная проверка

```sh
python3 -m unittest discover -s tests -p 'test_editorial_site.py' -v
python3 -m http.server 8000
```

Откройте `http://127.0.0.1:8000/`. Сайт не требует сборки JavaScript, API-ключей или запросов сторонним сервисам для чтения статей.
